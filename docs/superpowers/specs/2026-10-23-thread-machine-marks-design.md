# Thread machine marks

Approved design: add a separate machine glyph next to thread titles in the sidebar and a compact mark in the thread header, without editing titles or replacing provider/status glyphs. Classify hosts by stable BB host ID as local, primary or other; unknown/unassigned environments must never be classified as local. Default glyphs are laptop/server/cloud. Offer a small fixed palette and per-host roles/icon overrides in plugin settings. All names and assignments are runtime configuration, never source defaults. Disabled by default until configured.

Use public SDK sidebar data, content-script lifecycle for additive DOM decoration, an app overlay as the shared data controller, a header action and settings section. Scope selectors to native thread rows; unsupported DOM shapes produce no decoration. Create nodes with textContent; never render host names as HTML. Preserve title editing, navigation, statuses and model marks. Schedule at most one reconciliation per frame, write only changed values, remove owned nodes/listeners/observers on unload. Hooks refresh on sidebar/settings changes and host renames; no per-row network polling. Header can read its thread environment via one bounded RPC when sidebar data does not cover it.

Settings persist via the existing plugin storage and validated RPC. Store one bounded JSON string, use complete validated snapshots to prevent accidental loss of unseen host mappings, report invalid saved data and failed reads/saves distinctly. No task creation, environment move, model changes or machine enrollment.

Deliver general code in the public Projects source and the same isolated module as an owner-requested extension of the installed private Projects preserving its team integration. Production host identities remain private settings. Focused policy/DOM/lifecycle/settings tests, SDK registration/typecheck/build, CI and independent review precede releases. Live visual checks cover actual provider/status coexistence, light/dark, narrow/wide and cleanup; synthetic third-host cases are explicitly distinguished.
