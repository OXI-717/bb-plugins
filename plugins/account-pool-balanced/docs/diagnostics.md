# Замер очереди до и после изменения

Используйте одну команду с коротким допуском `read` через существующий
`management execute --request-stdin` (см. [допуски](management-access.md)):

```text
bb pool diagnostics --from 2026-01-01T00:00:00Z --to 2026-01-02T00:00:00Z --compare-previous --json
```

В приватном stdin-запросе `argv` содержит `diagnostics`, `--from`, начало,
`--to`, конец и `--json`. Не передавайте токен в аргументах процесса.
Команда всегда возвращает JSON. Начало включено, конец исключён; границы —
целые часы UTC, интервал положительный, до 14 суток.

Флаг `--compare-previous` сравнивает заданный период с предшествующим окном той же длины в одном вызове. Оба окна имеют собственную coverage; дельты означают после минус до. Если провайдер отсутствует в прошлом окне, дельта null, а не выдуманный ноль. Свежие события прошлого окна не восстанавливаются из истории. Сохраните
ответы в приватных артефактах приёмки. Команда сама не создаёт нагрузку.
История объединяется по провайдеру из часовых строк provider/account;
clientHash/projectId недоступны. Выполняется один линейный проход без сортировки, максимум 65536 строк,
64 MiB хранения. Среднее ожидание — сумма queueWaitMs / queueWaits, а не
percentile. Незавершённый час содержит только уже записанные события.

Свежие события ограничены кольцом 2048 строк / 24 часа. Отчёт показывает
измеренные queue-wait, guard-check с фактической фазой и auth-refresh.
Этапы могут пересекаться и не складываются в полное время запроса.
Отсутствие этапа означает отсутствие образцов. Глубина очереди аккаунтов —
текущий снимок, а не историческая метрика. Сводка не включает имена,
credentials, сообщения ошибок и тела ответов провайдеров.

Сверяйте observedAt, oldestAt/newestAt, startedAt, extendedCountersStartedAt,
rowsRead, усечения, вытеснения и ошибки хранения. Нулевые счётчики потерь
относятся только к указанному источником сроку; они не доказывают полноту
за всё время. История не хранит время последнего отдельного события.
Пустые данные не доказывают отсутствие запросов. Источники снимаются
последовательно; это не транзакционный снимок всех подсистем.

`update` показывает только идентификатор, начало и состояние уже существующей
операции штатного обновлятора; null означает отсутствие записи или недоступность
наблюдателя. succeeded подтверждает завершение обновлятора, но не успешный
запрос модели. Запускайте обновление существующей кнопкой; эта команда не
запускает обновление, не приостанавливает сессии и не меняет настройки.
