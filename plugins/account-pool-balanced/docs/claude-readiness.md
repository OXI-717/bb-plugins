# Claude client readiness

When Claude routing is enabled, managed Claude launches retain the pool URL and scoped token even if no account is currently usable. Temporary account unavailability therefore produces a pool refusal rather than silently dropping pool configuration and exposing local authentication as the next path. Explicit routing-off and intentional thread bypass retain their existing behavior. This does not control independently launched applications outside BB.

The bounded request journal may record a clientVersion extracted from a short Claude CLI user-agent. This field is self-reported and must never authorize a request or stand in for trusted machine identity. Caller binding remains the authenticated context and its existing client hash. Unknown, oversized or malformed versions become null. Raw user-agent strings, device identifiers, headers, prompts and credentials are not persisted by this feature. Old retained rows without the additive field remain valid. Existing journal retention, row/byte limits and error isolation are unchanged.

A host readiness audit should resolve the actual executable, record its version and run the shell doctor command with a finite deadline, without automatically applying suggested repairs or launching model prompts. Record warnings separately from the process exit code: a successful exit can still report duplicate installations. Keep full diagnostic output private on that host. Offline hosts remain unverified; absence from the available-host snapshot is not a successful audit. A successful doctor check is an installation diagnostic, not proof of account authorization, safe traffic volume or immunity from provider enforcement.

Align managed client versions through supported installation tooling after reviewing active use. Never merge machine identifiers or copy authentication directories to make machines appear identical. The existing two-request account cap and provider cooldowns remain in force. Additional request pacing and periodic host checks are separate follow-up work; this release does not add them or promise zero upstream errors.
