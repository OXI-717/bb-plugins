# Доступ к управлению Pooler

Обычная рабочая сессия не получает инвентарь аккаунтов, адреса прокси, привязки проектов и тредов, настройки, историю запросов или право изменять маршруты. Открытые `status` и `readiness` возвращают только `{ "management": "locked" }`. Подробная диагностика требует отдельного допуска.

## Разблокировка оператора

При первой инициализации плагин создаёт случайный ключ администратора в своём закрытом серверном хранилище: `<dataDir>/plugins/<plugin-id>/secrets/accounts/management/operator.env`. Каталог создаётся с правами `0700`, файл — `0600`. Ключ не выдаётся через API, настройки BB, обычную команду статуса или окружение провайдера. Открытого HTTP bootstrap нет. Существующий ключ сохраняется при обновлении; небезопасный или повреждённый файл не заменяется автоматически. Ошибка подготовки ключа закрывает управление, сохраняя работу уже настроенного модельного доступа.

Администратор передаёт ключ в приватное поле «Ключ администратора» в настройках. После разблокировки вкладка хранит только случайный допуск на 15 минут в памяти. Обновление страницы, истечение срока, отзыв или перезапуск плагина требуют новой разблокировки. Кнопка «Заблокировать управление» отзывает допуск на сервере. Ключи и допуски не сохраняются в localStorage/sessionStorage. Старый кэш инвентаря аккаунтов удаляется при открытии настроек.

Ключ администратора нельзя передавать модели, печатать в терминале, помещать в аргументы процесса или обычные переменные окружения сессии. Административная сессия получает только короткий допуск нужного уровня: `read` для диагностики, `manage` для изменений. Допуски существуют только в памяти сервера; хранятся их SHA-256 отпечатки. Они не удостоверяют номер BB-треда: это bearer-доступ, доверять переданным `threadId`, `projectId`, `cwd` или `Origin` плагин не пытается.

## CLI для допущенной сессии

Используется один приватный JSON-запрос через stdin; значения не входят в командную строку:

- `bb pool management unlock --request-stdin`: `{ "key": "<operator-key>", "scope": "read", "ttlSeconds": 300, "output": "<new-private-file-on-pool-server>" }`. Новый файл содержит допуск; существующий файл не перезаписывается. Команда возвращает только срок и уровень допуска.
- `bb pool management execute --request-stdin`: `{ "token": "<short-lived-grant>", "argv": ["account", "list", "--json"] }`. Импорт credentials или OAuth-кода также передаётся внутри этого приватного JSON, без второго stdin-флага.
- `bb pool management lock --request-stdin`: `{ "token": "<short-lived-grant>" }`.

Файл выдачи находится на сервере пула, даже если CLI вызван с другой машины. Передача допуска допущенной сессии — отдельное приватное действие администратора. В JSON нельзя вставлять секреты в тексте задачи или чата. CLI с подставленным номером разрешённого треда или без номера треда не получает прав. `--help` не выполняет операцию.

## RPC и соседние плагины

Старые прямые административные RPC закрыты для клиентских вызовов. Интерфейс использует `management.unlock`, затем `management.call` с краткоживущим допуском и `management.lock`. Вход и выход вызываемого метода проверяются исходным контрактом. Неизвестный метод и поддельный/истёкший допуск закрыты; `read` не даёт выполнять мутации. Отзыв запрещает новые операции и выдачу результата незавершённого чтения; уже принятая мутация может завершиться.

Проверенная сервером идентичность плагина `model-connections` сохраняет доступ только к `status.get` и `thread.account`. Протокол `claimNativeUnlock` по-прежнему допускает только проверенного `oxi-op`. Переданные пользователем поля с такими именами не являются этой идентичностью. Хост без проверенного caller отказывает этим необязательным интеграциям.

Общий протокол списка квот возвращает пустой инвентарь и не обновляет аккаунт по переданному ID. Подробные аккаунты и квоты доступны в разблокированных настройках Pooler. Индикатор аккаунта треда скрыт, пока управление заблокировано. Реквизиты аккаунтов не сохраняются в браузерном кэше.

Штатный серверный обновлятор читает закрытый ключ локально, получает короткий допуск на каждую команду и отзывает его после команды. Секреты не входят в аргументы или журнал обновления. При обновлении старой версии до появления этого ключа сохраняется прежний протокол; после появления ключа ошибки нового допуска не вызывают возврата к открытому протоколу.

Первую установку защиты поверх старой версии выполняют обновлятором из этой принятой ревизии. Старый уже замороженный обновлятор не умеет предъявлять новый допуск после перезагрузки плагина: старой кнопкой обновления выполнять этот переход нельзя. В дальнейшем кнопка использует новый обновлятор. Перед первым выпуском необходима проверка перехода и восстановления сессий этим новым обновлятором; публикация тега сама по себе такую проверку не заменяет.

Старый парный `scripts/upgrade-protection.sh` напрямую вызывает административные команды и после установки этой границы сам по себе не совместим. Для текущего выпуска используется `upgrade-pool.sh`; парный скрипт нельзя считать проверенным способом последующего обновления VPN Guard.

## Пределы защиты

Это ограничение интерфейсов плагина, а не изоляция произвольного кода одного системного пользователя. Код с доступом к файлам BB Server может прочитать или изменить серверное хранилище, запустить локальный обновлятор либо воспользоваться общими административными API самого BB. Скрытие справки или проверка номера треда этого не исправляют.

Ядро BB не менялось. Запись служебных токенов в `provider.env-resolved`, существующие журналы, глобальные правила владельца, права файлов других компонентов и общие API BB этим изменением не защищены. Старые токены не отзываются и старые журналы не удаляются автоматически. Новые ключи управления не передаются провайдеру и не добавляются в его стартовый контекст.
