# Выходной профиль аккаунта

## Подготовленное native исполнение

У `bb pool native configure <executor-json>` есть необязательный серверный
`execution`: `runtimeId`, `gatewayId`, `runtimeSha256` (64 lowercase hex) и
`profile: {id, version}`. Профиль должен уже существовать и поддерживать host
executor. По умолчанию эта возможность не настроена и ничего не включает.
Хэш относится к точному приватному preparation manifest доверенного исполнителя,
включая runtime files/toolchain, workspace, собственный профиль и gateway.

Аутентифицированный `/native/agy` возвращает снимок `binding` только для такого
executor: schema `bb-account-pool/native-execution/1`, leaseId/sessionId,
executorId/accountId/hostId, runtime/gateway/hash/profile, kind и server caller.
Acquire и heartbeat повторно проходят прежний admission. Каталог не получает
право задачи; после restart/expiry неопределённый слот не объявляется свободным.
Изменение занятого executor запрещено; snapshot не подменяется текущими labels.

Доверенный native launcher должен сверить grant с подготовленной средой до Popen
и отправки, закрывать канал между prompt и при утрате lease. Имя, URL или env
клиента прав не дают. Реестр подтверждает назначение, не измеряет удалённый IP
и не доказывает, что официальный протокол работает через CONNECT. Неподготовленный
launcher отказывает, а не игнорирует серверную привязку. Native модель и tools
должны использовать одну ограниченную среду; хостовая сеть BB остаётся прежней.
Секреты, пути профилей и unlock в response отсутствуют. Live AGY, отдельный
keyring, удалённый транспорт и активация требуют отдельной операционной приёмки.

## Центральные HTTP-клиенты

Для нового разговора Pooler выбирает аккаунт по прежней политике. Для центральных Claude/Codex
сервер затем получает назначенный профиль из своего реестра, а не из клиентского
заголовка или названия модели. Тот же транспорт получает доступная проверка квот
и обновление токена. Guard, проектные ограничения, выданное назначение клиента,
opt-ins, квоты, общая очередь и интервал начала запросов остаются обязательными.
Наблюдение quota headers и Retry-After сохраняется также при отказе маршрута.

Профиль версии 1 поддерживает один тип: SSH LocalForward к HTTPS CONNECT gateway.
Endpoint — только loopback HTTP-порт без пароля; это транспорт туннеля, TLS модели
не перехватывается. DNS и публичный IPv4 разрешает доверенный gateway на узле;
IPv6 и обход через NO_PROXY/direct запрещены. Глобальное окружение BB не меняется.
Сеть инструментов, Git и пакетов не перенаправляется этим серверным dispatcher.

В существующей карточке аккаунта выбирается профиль, показываются версия,
поддержанные хосты и предел проверки. Настройка доступна также через штатный CLI:

- `bb pool egress status --json` — реестр, привязки и закреплённые разговоры.
- `bb pool egress configure <profile-json>` — добавить неизменяемую версию.
- `bb pool egress bind <account-id> <profile-id> <version>` — новые разговоры аккаунта.
- `bb pool egress unbind <account-id>` — вернуть новые разговоры к прежнему маршруту.

Шаблон JSON: id/version/label/node/hostIds/transport=ssh-connect,
endpoint=http://127.0.0.1:19081, dns=remote, ipv4=true, ipv6=false,
failure=closed, expectedExit=["192.0.2.1"], assurance=proxy-enforced.
expectedExit описывает ожидаемый адрес, а не результат проверки. Ни доступность
узла, ни реальный публичный адрес, ни ответ модели автоматически не измеряются.

Начатый запрос и закреплённый разговор сохраняют account/version. Привязки
разговоров сохраняются в хранилище и после перезапуска сервера. Ошибка назначенного
профиля не разрешает выбирать другой аккаунт. Сохранённый assigned pin проверяется
до обычного selector, включая истечение его 30-минутного affinity TTL и restart.
Прежний аккаунт повторно проходит обычные family/project/purpose, opt-in, расписание,
квоты и reserve-проверки. Недоступный или неподходящий аккаунт даёт отказ до отправки;
Guard, очередь, cooldown и pacing также проверяются прежним путём перед отправкой.
Новая версия профиля или unbind не меняют сохранённый pin. Ошибка назначенного
транспорта, HTTP-отказ и прерывание потока не создают replay, смену аккаунта или
маршрута. Регистр ограничен 4096 решениями и 240 KiB JSON с запасом до
границы SDK KV 256 KiB. При исчерпании новые назначенные CONNECT-разговоры
отказывают без direct fallback; тёплые записи не вытесняются.
Обычный неназначенный трафик продолжает работать и не расходует новую квоту:
перед прекращением записи его снимков сохраняется запрет новых назначений.
Этот запрет переживает restart; восстановление назначения требует согласованного
завершения старых разговоров и подготовки свежего регистра, автоматического reset нет.
Разговор, начатый до назначения профиля, сохраняет прежний
маршрут также после назначения и перезапуска; новый профиль получают новые разговоры.
Неназначенный разговор сохраняет прежнюю политику выбора и failover Pooler;
он остаётся без профиля и при выборе другого аккаунта после нового назначения. Другие
провайдеры не занимают этот регистр и не блокируются его заполнением.
Настройка не удаляет провайдеры или модели и не включает аккаунты/расписания.

Доставка должна проходить после отдельного GO с проверкой активных операций:
разговоры, начатые до установки этой версии, сначала завершаются на старом
маршруте. Новый туннель проверяют без provider credentials, затем назначают
одному разрешённому аккаунту. Для отката новые разговоры возвращают штатным CLI,
старый транспорт держат до окончания закреплённых разговоров. Автоматического
перезапуска работающего пула нет.

Официальный AGY этим центральным транспортом не поддержан: модельный протокол
и наследование proxy инструментами не доказаны. Его действующий native admission
и вход не меняются; выбор профиля для него недоступен. Поддержка native выхода
требует отдельной проверки официального клиента и согласованного окна владельца.

## HTTP/HTTPS-прокси отдельного аккаунта

В настройках аккаунта Claude или Codex есть поле «HTTP/HTTPS-прокси аккаунта».
Оператор вводит URL, при необходимости с Basic-авторизацией. SOCKS, URL с путём,
query/fragment и IPv6-литералы не принимаются. Пароль не возвращается в статус,
список профилей или provider environment: сервер сохраняет его отдельным файлом
с правами 0600 в каталоге 0700. Для смены пароля сохраняют новый URL: создаётся
новый неизменяемый профиль. Старый нужен начатым разговорам до их завершения.

Операторский RPC `egress.proxy` принимает `{accountId, url}` и назначает профиль
данному аккаунту на серверном хосте. Не передавайте секретный URL через CLI
аргументы или чат. Для удаления назначения используют существующий выбор
«Текущий маршрут Pooler»; это меняет только новые разговоры.

CONNECT-транспорт явно назначен каждому запросу: `HTTP_PROXY`, `HTTPS_PROXY`,
их строчные варианты и `NO_PROXY=*` окружения сервера не могут подменить его
или разрешить прямой обход. Ошибка прокси закрывает запрос без смены аккаунта
и повторной отправки. Проверки VPN/Guard, проектов, квот и расписаний сохраняются.
HTTP и HTTPS в адресе обозначают соединение с прокси; TLS к провайдеру проверяется
обычным способом, отключения проверки сертификатов нет. DNS имени прокси
разрешает сервер Pooler; имя назначения передаётся CONNECT-прокси.

### Запуск Claude из BB

Официальная документация: <https://code.claude.com/docs/en/network-config#environment-variables>.
Claude поддерживает HTTP/HTTPS и Basic auth, не SOCKS. Строчные переменные имеют
приоритет. Это описание поддержки, а не требование всегда использовать прокси.

В режиме Pooler локальный Claude получает `ANTHROPIC_BASE_URL` и отдельный
`ANTHROPIC_AUTH_TOKEN` через штатный resolver BB при запуске/возобновлении и
получении моделей, включая удалённые хосты. Аккаунт выбирается сервером после
запроса клиента. Поэтому персональный URL прокси НЕ копируется в HTTP_PROXY
локального процесса: это перенаправило бы соединение с самим BB и раскрыло бы
пароль в событиях `provider.env-resolved`. Pooler передаёт настройки выбранного
аккаунта напрямую CONNECT dispatcher при модельных запросах, квотах и refresh.

Эта функция не настраивает прямой Claude вне Pooler, браузерный OAuth до создания
аккаунта, сеть инструментов/MCP, телеметрию локального клиента и фонового supervisor
Claude. Для таких процессов нужны отдельные настройки хоста и отдельная приёмка;
глобальные пользовательские settings.json здесь не изменяются. Локальные сетевые
переменные для доступа к серверу BB остаются политикой хоста.

Перед подключением нового аккаунта требуются рабочий адрес прокси, проверка
выхода и минимальный живой запрос через него. Сохранённый профиль сам по себе
не доказывает работоспособность, нужную страну выхода или доступность аккаунта.
Существующий VPN Guard продолжает требовать собственное разрешение.
