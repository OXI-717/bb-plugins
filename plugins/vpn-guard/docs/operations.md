# VPN Guard operations and limits

VPN Guard is a separate BB 0.46+ plugin. It starts in **Observe** mode. `bb vpn-guard status --json` and the VPN Guard panel show the mode, every enrolled machine's status, provider opt-outs owned by Guard and stopped turn IDs. `bb vpn-guard enforce` opts in; `bb vpn-guard observe` turns enforcement off and restores only provider opt-outs recorded in Guard's journal. The panel has the same controls. Do not enable it until the VPN status writer is installed on every machine that will run protected work. Install with `bb plugin install ./plugins/vpn-guard` from this checkout; an installed managed version needs its own immutable per-plugin tag.

The host entry reads only `~/.local/state/vpnks/vpn-state.json` on **that host**. Schema is `oxi-vpnks/vpn-state/1`, `updated_unix` is seconds, and `state` is `connected` or `disconnected`. Only fresh `connected` (0–60 seconds old) allows protected work. The opened inode must be a root-owned regular file, without group/world write permission, at most 4096 bytes; symlinks and future timestamps fail closed. Reads are bounded to 4097 bytes, overlapping stalled reads coalesce, and a one-second timeout returns `unknown`. There are no external VPN probes or network requests from the status check.

Enforcement checks the target host at each `message.dispatch` checkpoint. Protected sends wait in BB's queue while the status is disconnected or unknown. A five-second reconciliation loop checks all hosts, stops already-running protected threads on bad hosts, and uses `providers.setEnabled` to hide protected providers globally when any host is bad. It writes a journal before disabling each previously enabled provider. Kimi and Z.ai provider IDs are not changed. Previously disabled provider opt-outs stay disabled on recovery. Stopped turns are recorded but never replayed automatically. The guard keeps its own plugin loaded; do not disable it while it owns queued messages, because BB can orphan-sweep plugin waits.

Provider opt-outs are global in BB. A bad remote host therefore also hides protected providers on healthy machines. An unavailable remote writer yields `unknown` on that remote machine; the server's own VPN state is never substituted. The default protected IDs are `codex`, `claude`, `claude-code`, `cursor`, and `devin`. A generic ACP provider with another ID needs a separate policy and is outside this version's protection. The Account Pooler 0.4.13 continues to gate its own model, OAuth, usage, profile, reset, and background requests independently. Guard does not read or change pool settings, accounts, or secrets.

**Boundaries:** A user's explicit Send-now bypasses `message.dispatch`. Detection takes up to five seconds for active turns and provider opt-outs, plus host RPC latency. In-flight connections and native provider maintenance already running may continue. `providers.setEnabled` prevents new turns but has not been shown to terminate existing bridge processes or intercept independent usage/login/model network calls. Script automations already running are untouched; future agent automations pass through the message hook, while script mode does not. Neither a provider opt-out nor this plugin is a packet firewall. Keep a VPN kill switch for traffic-level enforcement.

The journal contains only provider IDs and stopped turn IDs in plugin KV. Recovery re-enables an ID only when Guard recorded disabling it and the supplying plugin remains enabled. BB's provider API has no compare-and-swap revision or actor history: a user's redundant manual disable while Guard already holds an opt-out is indistinguishable. Review the journal/status before changing provider toggles during a block. Crash recovery reuses the journal; do not delete plugin data while provider opt-outs are owned.

The tests use a fake SDK and synthetic hosts. They verify admission, host separation, stop selection, prior opt-outs, restart journal, malformed state and bounded reads. They do not prove native bridge resource release or full network denial. The plugin is deliberately not installed or enabled on a working BB by the build/test steps.
